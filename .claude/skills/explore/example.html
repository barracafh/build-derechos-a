Arena backend

Exploration of a multiplayer game backend: services, match flow, load, cost and traffic. All numbers are invented.

What this is

The backend that puts players into fair, fast online matches, for up to 50K players at once.

The problem

Players quit when they wait too long for a match or when the game lags. Evening peaks in three regions need many servers, but idle servers cost money all day.

The solution

Small stateless services handle accounts, the queue and the store. A matchmaker groups players, and an allocator starts game servers only where and when they are needed.

Who it is for

Engineers who build and run the backend, and anyone who needs to know where cost, lag and risk come from.

How it works

  1. Sign inThe game talks to one gateway that checks who the player is.
  2. Find a matchThe matchmaker groups players of similar skill and connection quality.
  3. Start a serverThe allocator hands out a ready game server in the player's region.
  4. PlayThe game server updates the match 30 times per second: the tick rate.
  5. Pay and stayThe store sells items; cost and retention show if the game is healthy.

Terms used on this page, in plain words. Underlined words elsewhere on the page link here.

Concurrent players (CCU)
Number of players online at the same moment. The fleet is sized for the peak.
Gateway
The single entry point for all web requests. It checks identity and applies limits before it passes a request on.
Stateless
A service that keeps no memory between requests. Any copy can answer, so it scales by adding copies.
Matchmaker
The service that groups waiting players into fair matches by skill and connection quality.
Allocator
The service that picks a free game server in the right region for each new match.
Warm pool
Game servers that are already running and idle, so a match starts without waiting for a new machine.
Tick rate
How many times per second the game server updates the match. 30 Hz means once every 33 ms.
Ping
The round-trip time between a player's device and the server, in milliseconds. Lower is better.
p95
The value that 95% of cases stay under. A p95 latency of 12 ms means 1 request in 20 takes longer than 12 ms.
rps
Requests per second.
Day-1 / Day-7 retention
The share of new players who come back 1 or 7 days after they install the game.
UDP
A fast network protocol for real-time traffic. It drops late packets instead of waiting for them.

Goal

Design the backend for a multiplayer arena game: 50K concurrent players across EU, NA and APAC, matches in under 30 s.

Users

  • Players on PC and console
  • Live-ops team: offers, events, balance
  • Platform engineers: fleet and cost

Scope

  • In: gateway, matchmaking, allocation, game servers, profile, store, telemetry
  • Out: client anti-cheat, social features, web shop

Components

  • Stateless services behind one API gateway
  • Authoritative game servers at 30 Hz, one process per match
  • Postgres for players and purchases; Redis for queue tickets

Flows

  • Join a match: queue → match → allocate → connect over UDP
  • Match lifecycle: allocated → warmup → live → ended → reported

Numbers

  • All numbers are invented for exploration. Replace them with load-test data.

Decisions

  • One gateway for all HTTPS traffic
  • Server-authoritative simulation; the client is never trusted
  • Postgres is the source of truth

Open questions

  • One fleet per region, or shared spot capacity in the APAC trough?
  • Elo or a TrueSkill-like skill model?
  • Add a read cache before Postgres?
