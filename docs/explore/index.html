Derechos · akorda

Aid finder for the Build night: chat in, verified public aids out. BDNS counts are measured from the public API on 2026-10-21; the build time is an estimate and is labelled so. The build delivers specs S0–S3; S4 only if time allows.

What this is

A chat that tells people in València which public aids they could apply for, and where.

The problem

Aids are spread across the State, the Generalitat and the city council, each with its own website and deadlines. The biggest ones are benefits, which never appear in the BDNS, the national register of grants.

The solution

The citizen writes their situation. The AI turns it into a short profile; rules check each aid in the catalogue, and live calls come from the BDNS. Every answer says "you could apply", shows what to check and links the official page.

Who it is for

Citizens of València and the Comunitat Valenciana. This page is for the akorda team and the Build night jury, to see how the tool works and what ships first.

How it works

  1. Tell your situationOne message in your own words, for example "24, unemployed, renting in València".
  2. We note what you saidThe AI fills a short profile, and only with facts you actually wrote.
  3. Each aid is checkedAn aid leaves the list only if something you said rules it out: the double block.
  4. Live calls are addedOpen calls from the BDNS, with their status taken from official dates.
  5. Honest answerWhat you could apply for, what to check, and what we could not check: the coverage panel.

Terms used on this page, in plain words. Underlined words elsewhere on the page link here.

BDNS
Base de Datos Nacional de Subvenciones: the public register where every Spanish administration must publish its grant calls. Free API, no key.
Convocatoria (call)
The official notice that opens an aid: who can apply, requirements, deadline and how to apply.
Ficha
The detail page of one call in the BDNS, with dates, documents and links to its rules. The search results do not include deadlines, so each result needs its ficha.
Bases
The legal text of a call, usually a PDF, with every requirement. Requirements such as age or income live only here.
Benefit (prestación)
An aid that is a right set by law, such as the IMV or unemployment pay. It is not a grant, so it never appears in the BDNS.
Instrumental call
A BDNS entry that only records a payment already decided, for example to an association. Citizens cannot apply to it.
The "abierto" field
A BDNS field that only means "no fixed deadline". It does not mean the call is open today; status must come from the dates.
Purpose (finalidad)
The topic code of a call in the BDNS: housing (8), social services, education, employment, and so on.
IMV
Ingreso Mínimo Vital: State benefit for households with very low income, managed by the Social Security.
RVI
Renta Valenciana de Inclusión: regional minimum income. Its law changed on 20 Oct 2026, so it is shown as unconfirmed.
SEPE
Servicio Público de Empleo Estatal: the State employment service that pays unemployment benefits and subsidies.
IPREM
A public income index that many aids use to set income limits, for example "up to 3 times the IPREM".
Generalitat (GVA)
The regional government of the Comunitat Valenciana (CV).
BOE / DOGV
The official gazettes of the State and of the Generalitat, where laws and calls are published.
Sede electrónica
The official website of an administration where a procedure is actually done.
IGAE
Intervención General de la Administración del Estado, which runs the BDNS. Its terms ask us to cite it as the data origin, with the consult date.
Benefits catalogue
The organisers' file with 8 aids and 13 procedures for València, checked by hand on 18 Oct 2026. It covers the benefits the BDNS lacks.
Pack
The data the organisers ship with the challenge, in the datos/ folder: the catalogue and a dated copy of 59 BDNS calls.
LLM
Large language model: the AI. Here it only reads the citizen's message and returns structured data; it never writes what the citizen reads.
HelmCode
The AI provider of the event. Its chat model is glm5.3-flash; it also offers embeddings and rerank. All teams share its limits.
Profile
What we know about the citizen in this chat: age, job, housing, children, income band, town. Every field is optional and nothing is stored.
Double block
The rule that removes an aid only when a fact the citizen stated contradicts a verified requirement. Anything unknown keeps the aid in the list.
Coverage panel
A block in every answer that says which sources were checked and which were not, for example local aids outside València.
BM25
A standard keyword search that ranks texts by how well their words match the query.
Spec (S0–S4)
One unit of work with a goal, checkable requirements, its files and its tasks. One person owns it from start to finish.
Contract
The shared shapes that every part agrees on: Perfil, Ficha and Respuesta. If the contract holds, each person can build their part without waiting for the others.
Fixture
A saved example answer, for example the Respuesta for one test profile. The frontend draws it before the real engine exists.
Mock route
A stand-in /api/chat that returns fixtures instead of calling the AI and the BDNS. S3 replaces it with the real route.
Vibe coding
Building by describing what you want to an AI coding tool and checking the result on screen, without writing the code by hand.
Vercel / push to main
The platform that publishes the site each time code is pushed to the main branch. The organisers own the project.

Goal

A chat where a citizen describes their situation and learns which public aids (State, regional, municipal) they could apply for: why, what to check, status and official link. It must invent nothing and miss nothing. The Build night demo ships specs S0–S3; S4 only if time allows.

Audience

  • Team akorda, especially the non-technical members (content, design, testing): they know the challenge, not the BDNS, LLMs or each part of the tool
  • Organisers and the Build night jury: they know the track, not our solution
  • Assumed: no one knows the technical or administrative vocabulary; every acronym has a definition in the Glossary tab

Users

  • Citizens of València and the Comunitat Valenciana; the four test profiles of SETUP.md
  • Build night jury (demo on Thursday 22 Oct 2026)
  • Team akorda: Oscar, Albert, Alex, Tomás and Julia (captain), technical and non-technical

Scope

  • In: S0 contracts; S1 frontend; S2 engine and BDNS calls (catalogue rules, live BDNS for State + Comunitat Valenciana as SETUP.md describes); S3 LLM loop with guardrails and test set
  • If time allows: S4, a daily job that stores the aids no API gives (not BDNS calls) in src/datos/central.json, in the catalogue shape
  • Out for now: Postgres + pgvector, embeddings and rerank (until measured), dynamic vocabulary, catalogue pipeline with human validation, all of Spain
  • Out: form and button-driven flow; storing citizen text; DANA aid (link to sede.gva.es)

Components

  • S0: types Perfil, Ficha, Respuesta; fixtures for the 4 test profiles; mock /api/chat (data)
  • S1: Chat UI with aid cards, coverage panel, optional question, loading, error and unconfirmed states (service)
  • S2: candidate engine with the catalogue rules for the 8 aids (compute); live BDNS client (service); BDNS API (external); benefits catalogue and pack BDNS copy (data)
  • S3: /api/chat with the LLM interpreter glm5.3-flash (external), guardrails and test set (compute)
  • S4, optional: daily indexing job in GitHub Actions (compute) writing src/datos/central.json and read texts by hash (data)

Flows

  • Query: message → LLM (profile with quotes + need) → catalogue rules, double block → 3 BDNS searches → non-instrumental + need-to-purpose filter → up to 10 fichas → status from dates → rank by purpose and title keywords → cards + coverage + optional next question
  • Build order: S0 first → S1, S2, S3 in parallel → S1 switches from the mock to the real route → S4 plugs into S2 if time allows
  • Fallback: pack copy if the BDNS fails; BM25 on frases_usuario if the LLM fails

Numbers

  • Measured (BDNS API, 21 Oct): 12,137 for individuals in 2026; 1,988 since 1 Sep (26 State, 164 regions, 1,531 local); 285 in the Comunitat Valenciana since 1 Sep
  • Pack: 59 convocatorias, 14 instrumental, 27 with dates (17 expired by 22 Oct); catalogue 21 entries, 8 aids; one bases PDF ~17,500 words with a text layer
  • HelmCode docs: chat 100 RPM and 10 concurrent per key
  • Estimate: ~4 h build (SETUP.md); S0 ~1 h

Decisions

  • AI chat from the start; no form and no button-driven flow; the chat may ask optional questions (the field that resolves the most aids)
